# Upstream courtesy — on demand

Canonical policy: `body.md`. Portable generated copy:
`skills/upstream-courtesy/SKILL.md` (from repository root), rendered by
`python3 scripts/courtesy.py --render`. Keep the checked-in copy exactly equal
to that render; parity tests fail on drift.

This optional practice contributes **no prompt text**. It can be named alongside
engineering or research in an existing packs/lead_packs list, but is
not a standalone domain profile. The installers register the skill for normal
host discovery, independent of that selection. No default lead/worker awareness
line is added; unrelated leads need not load it. Only for an actual upstream
submission task should the lead load it and explicitly pass it to that worker.
This is a reusable on-demand practice, not a new mandatory workflow framework.

The portable skill needs no chief, service, Git repository or publishing tool.
Ask the principal/user directly when no lead/owner hierarchy exists. Host policy
and reserved approvals still apply. Skill discovery is not proof any particular
model will trigger; independent prompt review is pending.
