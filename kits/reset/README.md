# Lean managed roles

`scripts/lean_roles.py` is the ordinary technical installer renderer for chief and lead.
It uses these cores without legacy host bodies or automatic instruction includes.
Generic/principal and Pi lead compositions retain their separate isolation contract.
Changing source is not activation: no ordinary live install is authorized by this package.

`./install.sh --reset-pilot profiles/reset-pilot-chief.json` (or the lead manifest)
registers a unique local role and nine explicit-load procedures, never selects an agent
for a session, changes chief.json, or edits opencode.json. Existing files cause refusal.
`--dry-run` previews. `--uninstall` moves only receipt-matching owned files into
`.opencode/reset-install/<name>-archived/`, preserving bytes and the receipt. Changed files
refuse rollback. Use a fresh role name after archival; no archived evidence is overwritten.

OpenCode loads `reset-*` procedures explicitly by native ID; `opencode/autoinvoke:false`
keeps their descriptions out of the automatic catalog. Claude/Codex receive plain reference
files at the stable absolute directory printed in their role, outside skill discovery.
No procedure content is automatically appended. Existing kit catalog and Runway tool/schema
prose remain counted; on-demand procedures have no rigid size/count cap.

The optional `heartbeat` pilot manifest seam takes `source` (absolute installed candidate
path), `pilotSessionID`, and `enabled:false`. It writes a direct watched local JS wrapper,
does not edit config or copy/import the heartbeat author's evolving implementation, and
returns immediately while disabled. Enabling is deliberately unsupported until the owner
supplies a reviewed native factory/options contract. That contract must revalidate the
current valid chief.json at dispatch AND context authorization, bind this one opted-in
Location/session, and preserve unrelated sessions. A pointer path alone is not proof.

Preserve plain inbox/targeted messages until those bindings work. The iPhone
