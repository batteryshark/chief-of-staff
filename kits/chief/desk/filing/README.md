# Optional receive/file-only desk (source, not installed)

Explicit opt-in for any domain chief. No default prompt/config/agent/service is
changed. No autonomous answering. Native Knowledge Notes are primary; no Canvas,
Todo/Plan management or engineering assumptions. This ports the working narrow
pilot protocol, not the separate full native adapter. It is instruction-constrained,
not a security sandbox, and saved JSON is not native attestation.

## Manual opt-in

**INSTALL GATE:** this frozen 22fcfae-derived source package lacks the separately
installed canonical FIELD-capture port. Do not install/enable it for genuine
reports until that independent gate is resolved; do not substitute model-copied
JSON or claim raw bytes/native origin authentication. The running private pilot
is a separate implementation, not updated by source edits here.

1. Review these files first. Privately supply control from control.template.json:
   selected chief home, dedicated exact chief-route JSON (`session_id`, `directory`),
   read-only current open-items file, actual receiver ID, existing canonical project
   paths and current trusted lead IDs. Never repoint the real chief identity to the
   desk. These are operator observations/configuration, NOT report inputs. No
   public owner-schema changes. Start all projects disabled and mode DISABLED.
2. Separately initialize an ordinary managed receiver session using existing
   managed session tools, with explicit operator-selected model on FIRST SEND:
   promptless managed create discards selection. Verify actual persisted native
   identity/location/model and tool records; requested values, self-ID or cached
   instructions are not proof. This kit does not create sessions or make calls.
3. Stage into a NEW private empty root directly under your explicitly selected
   HOME (not a global chief path):
   `python3 kits/chief/desk/filing/stage.py --home /canonical/private/home --destination /canonical/private/home/new-filing-desk --config /private/control.json`
   This copies seven inert local files, no native/network/model action. Ancestors
   must be canonical, UID/root owned, non-writable by group/others, not links;
   leaves single-linked. Root 0700, files 0600, absent-only. Every target/source
   is preflighted before writing. Any failure/partial stage is NOT retried or
   reused: preserve/audit it; use another new destination after review. No
   overwrite, uninstall, automatic cleanup, migration or installer invocation.
4. Explicit operator assignment/review is required before activation. Under the
   shared writer.lock, while receiver actually idle, operator alone sets exact
   enabled mappings/mode LIVE. New Notes are distinct desk-owned items. Optional
   `handover` on a project requires exact note_id/body/body_hash and explicit
   authorization, from trusted native readback; never adopt by title/report.
   Do not put pilot repair IDs/secrets into config. Reconcile through admit's
   exact readback path; unresolved effects stay pending for auditable review.
5. Prove throwaway filing/update/duplicate/eligible question-once with actual
   managed calls and independent native readback before genuine routing. Supply
   the receiver these staged instructions and root; manual product initialization
   does not prove cached context reload. Only after evidence and explicit choice,
   give opted-in leads the receiver route; keep real chief identity separate.

## Producer handoff

Use existing managed session.send to configured receiver ID/directory with
returnResult:false, at milestones/material next/wait changes (not heartbeats).
Do not create another receiver or select recipient/model from a report.

```json
{"kind":"status","report_id":"fictional-study-001","project":"/fictional/study","lead_session":"fictional-study-lead","observed":"2026-10-01T09:00:00Z","landed":"Source inventory recorded.","next":"Compare methods.","your_part":null,"questions":[]}
```

Keep stable ID+body on duplicate delivery; changed content needs new ID. Only
explicit questions[] not already open/asked may be forwarded, never answered.
Unknown eligibility remains pending. Neither status requests nor report fields
can enroll projects, select Notes, recipients, admin actions or permission.

## Intentional port deltas / review gates

- No personal paths, pilot repair/supervised overrides, test-sink dispatch or
  historical operator-resume bypass. Explicit configurable selected chief sources
  and actual receiver, inert registry/schema, strict duplicate-key/input checking.
- Atomic fsynced state and dedicated shared lock; absent-only staging with path,
  UID/link/mode/count preflight. Trusted OS ancestors/same-UID operator assumed;
  not a hostile-process race-proof filesystem sandbox. Helper never owns native
  auth/client. Operator config, supplied observations and normal-agent compliance
  remain trust boundaries; source labels alone are NOT native attestation.
- Compact helper projections, no model whole-ledger reads. Durable originals,
  ordered admissions and receipts are retained without pruning; helper still
  parses/rewrites local state (linear growth). No wholesale event-store/migration.
- Mixed already-open and new questions stay pending for operator review rather
  than suppressing the new item or forwarding the already-open item. Current
  whole-question-chain review is deliberately conservative, not semantic proof.
- Status prior-ask phrases never suppress questions. Completed-forward evidence
  requires exact project AND lead plus normalized question coverage. Old heuristic
  suppressed receipts are not conclusive. Open-text substring/classification alone
  stays pending. See instructions.md for the exact question_review JSON/evidence
  shape: every reworded known question needs a retained current-hash observation
  with exact question/project/lead and a current scoped excerpt. No answer or
  approval authority, automatic replay, historical migration or new source API.
- Native Note bodies use the existing kit's 3000 UTF-16-unit bound. Recent digest
  keeps newest complete milestones that fit; all older originals and terminal
  digest lines remain private authoritative history, never dropped. Status that
  cannot fit stops with original retained; no silent truncation/summarization.
  Final-body ECMAScript trim avoids native body normalization mismatch.
- Independent review and real future native body/tool/action evidence required
  for this port; offline JSON fixtures do not certify runtime identity/delivery.
  No every-report Strong review requirement for ordinary no-answer filing.
  No staged files are a live install or permission to touch an existing pilot.
